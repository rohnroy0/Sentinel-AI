# Security Policy & Architecture Guidelines

## 1. Overview
Sentinel-AI is built with enterprise security, privacy, and multi-tenant data isolation at its core. Whether deployed in single-user local mode or multi-tenant cloud infrastructure, the platform enforces strict boundary controls, evidence validation, and secret hygiene.

---

## 2. Core Security Practices

### A. Multi-Tenant User Isolation & Data Protection
- **Strict User Scoping:** Every investigation record, vulnerability telemetry object, decision log, and attack graph generated by Sentinel-AI is bound to a validated `user_id`.
- **Database Layer Enforcement:** The `InvestigationRepository` and database adapters (`SQLiteAdapter` and `SupabaseAdapter`) reject all operations missing an explicit `user_id`.
- **Query Scoping:** Cross-tenant reads or writes are strictly prevented. Users can only query or modify investigation data bound to their authenticated principal.

### B. Authentication Architecture
- **Supabase Production Auth (`AUTH_MODE=supabase`):** Validates ES256/HS256/RS256 JSON Web Tokens (JWT) issued by Supabase Auth against JWKS endpoints.
- **Isolated Demo Auth (`AUTH_MODE=demo`):** Generates isolated, session-scoped temporary identities (`demo-user-{uuid}`) per browser session. Prevents shared state leakage or data mixing between evaluators.

### C. Secret Hygiene & Configuration Management
- **Zero Exposed Credentials:** API keys (`OPENAI_API_KEY`, `NVD_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`) are managed exclusively via environment variables and loaded through `backend/config.py`.
- **No Hardcoded Secrets:** Code repository contains no static JWT secrets, service keys, or database credentials.
- **Git Ignore Guards:** `.env` files, SQLite database files (`investigations.db`), and cache artifacts are strictly excluded via `.gitignore`.

### D. AI System Integrity & Evidence Validation
- **No Fabricated Findings:** The AI agent operates exclusively on parsed telemetry, deterministic rules, and verified CVE signatures (`cve_cache.json` / NVD API).
- **5-Point Explainable AI:** Every finding includes Finding Title, Root Cause Why, Verified Evidence, Exploitation Impact, and Actionable Remediation.
- **Cautious Language Engine:** Attack paths generate probabilistic claims ("may permit", "potential risk") backed by explicit MITRE ATT&CK technique mappings.

---

## 3. Reporting a Vulnerability

If you discover a potential security vulnerability in Sentinel-AI:
1. **Do NOT open a public issue.**
2. Send a detailed report to the security team via email at `security@sentinel-ai.local` or contact repository maintainers directly.
3. Include detailed steps to reproduce, affected components, and impact analysis.
4. We aim to acknowledge reports within 24 hours and issue a patch within 7 business days.
